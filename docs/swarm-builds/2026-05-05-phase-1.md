## Architectural decisions

Three non-obvious decisions:

1. **Reskin via token overrides, not component rewrites.** When upstream uses shadcn semantic tokens (`bg-card`, `text-foreground`), our `themes.css` re-declares those tokens at `:root` and `:root.dark` and gets the entire surface for free. When upstream bypasses tokens with raw Tailwind palette (`text-sky-600`), only those bypass sites need patching. This drove the "reskin → audit hardcoded → patch the bypasses" workflow instead of any per-component restyling.

2. **Trust upstream's existing theme system; don't build a parallel one.** I initially built a duplicate Settings → Appearance switcher with its own `appydave.theme` localStorage key and an `initializeTheme()` call in main.tsx. Upstream already has `apps/web/src/hooks/useTheme.ts` with `t3code:theme` storage and a Theme dropdown in Settings → General. Two systems writing the same `.dark` class fight each other. Deleted the entire duplicate; AppyDave reskin is purely token-level on top of upstream state.

3. **Cold-T3 stays in token reference, not user-selectable.** The POC ships three theme blocks (light / dark / cold-t3). We retired cold-t3 from the user-facing switcher since the upstream Theme dropdown only exposes light/dark/system, and cold-t3 represents the "before" state the AppyDave reskin is replacing. The token block stays in the POC reference for A/B comparison only.

## Reviewer findings

I drove this conversationally with the user (no `reviewer` agent), and the user *was* the reviewer — caught three real issues across UAT rounds:

- **Cold-T3 dark colors leaked through.** First fix attempted nesting `@variant dark` inside `:root` — turned out Tailwind's `@variant` directive only compiles for files that pass through Tailwind's pipeline, and `themes.css` was loaded as a plain CSS import. The `@variant dark` block emitted no rules. Switched to explicit `:root.dark` selectors which match the same compiled selector with identical specificity (0,1,1). Load order then decides; themes.css imports after index.css, so AppyDave wins.
- **Single-color wordmark.** First pass shipped `<AppyCtrlWordmark>` as one-color. Per AppyDave brand convention (Appy + Dave split), brand-aligned to two-color: Appy in foreground (`#3a2a1f` light / `#ccba9d` dark), Ctrl in primary (`#b8860b` / `#ffde59`). Theme-aware via `--appy-wordmark-*` CSS vars.
- **Surface-level token reskin missed hardcoded bypasses.** "Working" pill rendered sky-blue in dark mode despite the rest of the surface being warm. Triggered the deep audit (delegated to subagent) which catalogued 26 hardcoded Tailwind palette literals across 10 component files. Patches 1+2 (status pills + plan sidebar) shipped this phase; patches 3-6 deferred.

## Gotchas / watch out for

- **`@variant dark` does not work in plain CSS imports.** Anywhere we want a Tailwind variant to apply, the file needs to be processed by Tailwind. Use explicit `.dark`, `:root.dark`, or move the rule into index.css. Failure mode is silent: rule emits no CSS, dark mode falls back to upstream tokens.
- **Hardcoded Tailwind palette classes are everywhere.** A token-only reskin is incomplete. Audit method that worked: spawn an Explore subagent with the full grep pattern set (`text-blue-*`, `bg-emerald-*`, raw hex, etc.), have it group findings by semantic role, then prioritise patches by visual impact + rebase risk. The 26 we found suggest most other phases that touch UI will need a similar pass.
- **Sidebar.logic.test.ts uses synthetic ThreadStatusPill objects as test fixtures.** Tests construct their own `colorClass: "text-emerald-600"` etc. — they don't call `resolveThreadStatusPill()`. So changing the function's output strings did NOT break those tests. Lucky outcome; future palette-coupled tests may not be so lucky.
- **`@variant dark` inside `:root` block:** wasted ~1 hour. The fix that worked is the simpler one: top-level `:root` and `:root.dark` selectors, no Tailwind directive needed.
- **Vite HMR doesn't reliably pick up CSS cascade changes.** Three UAT rounds were partially confusing because the dev server cached stale CSS even after my fix landed. Lesson: when changing token cascade or selector specificity, full restart is mandatory, not optional.
- **`bun fmt` is repo-wide.** It touches design-poc and docs as well as source. Phase 1 commits are noisier than they should be because of formatter churn on `.appydave/design-poc/**/*.css|jsx`. Future: consider adding the design-poc tree to `.oxfmtignore` (or oxfmt's equivalent) so the reference bundle stays untouched.
- **Skill prune defaults are upstream-shape-dependent.** Ruflo upstream is mid-restructure (singular `plugin/` → 32 `plugins/*` packages). Today's `claude-flow@3.6.27` still ships the old layout, so prune defaults work. When npm catches up to the new layout, prune.sh's hardcoded category arrays will break — flagged in the Ruflo refresh-upstream output.
