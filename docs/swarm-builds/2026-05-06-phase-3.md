## What was built

Wired the click handler in the Application launcher sidebar (Phase 2 left it as a no-op). Two execution paths:

- **`openExternal: true`**: `handleActivate` calls `window.desktopBridge.openExternal(url)` — reuses upstream's existing IPC channel, no new plumbing needed.
- **`openExternal: false`**: `handleActivate` navigates to `/apps/$id` (new TanStack file-based route). The route renders `WebviewPane`, which sends `appy:show-webview` IPC to the main process. Main creates a `WebContentsView` positioned over the main panel using bounds from `getBoundingClientRect()`, loads the URL, and manages the view lifecycle (show/hide/resize) via three IPC channels.

New files:

- `packages/appydave/src/bridge.ts` — `AppyDesktopBridge` interface + `Window.appyBridge` global
- `apps/desktop/src/appydave/appyBridge.ts` — preload `contextBridge.exposeInMainWorld("appyBridge", {...})`
- `apps/desktop/src/appydave/appyIpcHandlers.ts` — WebContentsView lifecycle (show/hide/resize + navigation policy)
- `apps/desktop/src/appydave/externalBrowser.ts` — `validateAppyUrl`, `parseViewBounds` validators
- `apps/web/src/routes/apps.$id.tsx` — TanStack file-based route
- `apps/web/src/appydave/apps/WebviewPane.tsx` — React component with IPC, ResizeObserver, error/retry UI
- `.appydave/kdd/decisions/adr-0003-webcontentsview-for-embedded-apps.md`

## Architectural decisions

1. **WebContentsView over `<webview>` and BrowserView.** Researcher one-shot confirmed Electron 40.9.3. Both alternatives deprecated. Zero existing usage in t3code codebase → zero migration cost. ADR-0003 locked before fanout started.

2. **Reuse upstream's `OPEN_EXTERNAL_CHANNEL` for the external path.** `desktopBridge.openExternal` already exists and works. Adding `openInExternalBrowser` to `appyBridge` just to wrap it would have been indirection for its own sake. `handleActivate` calls `window.desktopBridge.openExternal` directly for `openExternal: true`. This saved a new IPC channel + handler.

3. **Contract-lock before fanout.** Bridge interface (`AppyDesktopBridge`), IPC channel strings, and bounds type locked verbatim in both coder briefs. Coder-A and Coder-B produced files that composed correctly at integration with zero rework — same result as Phase 2.

4. **Researcher one-shot value.** Without it, coders would have shipped `<webview>` tag (deprecated) or had to discover the Electron 40.x API themselves, costing each ~10–15 min of groping through docs.

## Delivery Review outcome

**FAIL** — 6 reject-class findings identified by the 6-dimension delivery review team (BH/EC/AA/AR/CQ/UT running in parallel). Feature is architecturally sound and TypeScript-clean; the failures are runtime issues in the Electron WebContentsView lifecycle:

- `shell.openExternal` called with unvalidated URL from `setWindowOpenHandler` (security)
- Missing `devicePixelRatio` scaling — broken on every Retina Mac
- `activeViews` Map not cleaned on webContents destroy (zombie processes)
- Wrong window used for `removeChildView` under focus change (UI corruption)
- Double-view stacking on rapid navigation (no dedup guard)
- AC-8 contract mismatch (`openInExternalBrowser` named in spec, not implemented)
